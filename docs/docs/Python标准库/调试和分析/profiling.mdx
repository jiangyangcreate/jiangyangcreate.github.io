Python 3.15 起，内置性能分析工具收归到 [`profiling`](https://docs.python.org/zh-cn/3/library/profiling.html) 包（PEP 799）：

| 模块 | 说明 |
| --- | --- |
| `profiling.tracing` | 确定性函数调用追踪（由原 `cProfile` 迁入） |
| `profiling.sampling` | Tachyon：高频统计采样分析器，可按 PID 附加、开销极低 |

`cProfile` 仍作为 `profiling.tracing` 的兼容别名；`profile` 已弃用，计划在 3.17 移除。统计数据仍可用 `pstats` 格式化为报表。

过去标准库的 `profile` 和 `cProfile` 两个追踪式分析器。纯 Python 的 `profile` 太慢，基本只剩教学用途，名字却更像「正式」入口；`cProfile` 快一些，但要记录每一次函数调用和返回，开销大，会让解释器的部分优化失效，而且只观察主线程。

新的采样分析器开销极低，支持多线程、异步和附加到正在运行的进程。`profiling` 包按分析方法把它们归到 `tracing` 和 `sampling` 两个名字下，一看就知道该选哪个。

## 命令行直接分析脚本

不改一行代码，直接从命令行分析整个脚本的性能：

```bash showLineNumbers
python -m profiling.tracing -s cumulative my_script.py
# 兼容旧写法：python -m cProfile -s cumulative my_script.py
```

`-s cumulative` 按累计耗时排序，快速定位最耗时的函数。如果想把结果存到文件以便后续分析：

```bash showLineNumbers
python -m profiling.tracing -o profile_result.prof my_script.py
```

### Tachyon 采样分析

需要低开销、甚至附加到已在跑的进程时，用 `profiling.sampling`（不必改代码、不必重启）：

```bash showLineNumbers
# 按 PID 附加（墙钟时间，默认）
python -m profiling.sampling attach <PID>

# 直接跑脚本并采样；--flamegraph 生成可浏览器打开的火焰图
python -m profiling.sampling run --flamegraph my_script.py

# 只看 CPU 时间 / GIL 占用 / 异常处理时间
python -m profiling.sampling run --mode cpu my_script.py
python -m profiling.sampling run --mode gil -a my_script.py
```

适合生产环境排查；确定性追踪（`profiling.tracing`）更适合开发期精确定位调用次数与累计耗时。

## 分析某段代码

用上下文管理器包裹你想分析的代码块，不需要侵入整个程序：

```python showLineNumbers
from profiling import tracing
from pstats import Stats, SortKey

with tracing.Profile() as pr:
    # 把你想分析的代码放在这里
    result = sum(i * i for i in range(1_000_000))

Stats(pr).strip_dirs().sort_stats(SortKey.CUMULATIVE).print_stats(10)
```

## 用装饰器分析单个函数

写一个可复用的装饰器，想分析哪个函数就套上去：

```python showLineNumbers
import functools
from profiling import tracing
from pstats import Stats, SortKey

def profile(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        with tracing.Profile() as pr:
            result = func(*args, **kwargs)
        Stats(pr).strip_dirs().sort_stats(SortKey.CUMULATIVE).print_stats(20)
        return result
    return wrapper

@profile
def process_data(n):
    data = [i ** 2 for i in range(n)]
    return sorted(data, reverse=True)

process_data(500_000)
```

## 读懂分析报告

```text showLineNumbers
   ncalls  tottime  percall  cumtime  percall filename:lineno(function)
   500000    0.062    0.000    0.062    0.000 {built-in method builtins.pow}
        1    0.031    0.031    0.120    0.120 example.py:12(process_data)
        1    0.027    0.027    0.027    0.027 {built-in method builtins.sorted}
```

| 列 | 含义 |
|---|---|
| ncalls | 调用次数（如 `3/1` 表示递归调用 3 次，原始调用 1 次） |
| tottime | 函数自身耗时（不含子函数） |
| cumtime | 函数总耗时（含子函数） |
| percall | 平均每次调用耗时 |

重点关注：**cumtime 大**的函数是整体瓶颈，**tottime 大**的函数是自身计算密集的热点。

## 用 pstats 做深度分析

将结果保存到文件后，可以反复筛选、排序：

```python showLineNumbers
import pstats
from pstats import SortKey

p = pstats.Stats("profile_result.prof")

# 按累计耗时排序，只看前 15 行
p.strip_dirs().sort_stats(SortKey.CUMULATIVE).print_stats(15)

# 只看某个模块或文件的函数
p.sort_stats(SortKey.TIME).print_stats("my_module")

# 查看谁调用了耗时最多的函数
p.print_callers("process_data")

# 查看某函数调用了哪些子函数
p.print_callees("process_data")
```

## 接口调优

假设你有一个处理请求的函数，响应时间忽然变长了：

```python showLineNumbers
from profiling import tracing
from pstats import Stats, SortKey

def handle_request(user_id):
    user = query_user(user_id)        # 数据库查询
    orders = query_orders(user_id)    # 数据库查询
    report = generate_report(orders)  # CPU 密集计算
    send_email(user, report)          # 网络 IO
    return report

with tracing.Profile() as pr:
    handle_request(42)

stats = Stats(pr)
stats.strip_dirs().sort_stats(SortKey.CUMULATIVE).print_stats(10)
# 如果 cumtime 大头在 query_orders → 优化 SQL 或加索引
# 如果 cumtime 大头在 generate_report → 优化算法或用缓存
# 如果 cumtime 大头在 send_email → 改为异步发送
```

### 对比优化前后效果

保存两次分析结果，用 `add` 方法合并或对比：

```python showLineNumbers
from profiling import tracing

# 优化前
tracing.run("old_implementation()", "before.prof")

# 优化后
tracing.run("new_implementation()", "after.prof")

# 分别查看对比
import pstats
print("=== 优化前 ===")
pstats.Stats("before.prof").strip_dirs().sort_stats("cumulative").print_stats(5)
print("=== 优化后 ===")
pstats.Stats("after.prof").strip_dirs().sort_stats("cumulative").print_stats(5)
```

### 可视化分析结果

将 `.prof` 文件转换为可视化图形（需安装第三方工具）：

```bash showLineNumbers
pip install snakeviz
snakeviz profile_result.prof
```

snakeviz 会在浏览器中打开一个交互式火焰图，比文字报告直观得多。采样分析也可用 `profiling.sampling` 直接生成 `--flamegraph` HTML，无需额外工具。
